# Маршрутник — маршрутный лист из выгрузки

Статический сайт: загружаете выгрузку заданий (.xlsx с колонками «Адрес задания», «Номер задания», «Исполнители», «Дата выполнения») — получаете заполненный «Отчёт о служебных поездках» (4 раздела, как в шаблоне).

Что делает:
- читает .xlsx / .xls / .csv; колонки (адрес, дата, время, номер наряда, исполнитель) находит сам по заголовкам в любом порядке, а без заголовков — по содержимому; определение можно поправить вручную;
- выбирает задания нужного сотрудника за нужный месяц и раскладывает их по дням в порядке времени выполнения;
- в начало дня ставит выезд с базы (0 км), в конец — возврат на базу; адрес базы вводит пользователь;
- километры считает сам по дорогам между соседними точками (OpenStreetMap: Nominatim/Photon + OSRM), возврат — от последней точки дня до базы;
- любое расстояние можно исправить вручную — оно запомнится для этой пары адресов;
- сумма = км × стоимость 1 км (стоимость вводит пользователь); скачивается .xlsx с формулами.

Файлы обрабатываются в браузере. Наружу уходят только адреса — в OpenStreetMap для подсчёта расстояний.

## Статистика (Яндекс Метрика)

1. Зайдите на https://metrika.yandex.ru → «Добавить счётчик», адрес сайта — `маршрутник.рф`. Вебвизор не включайте: он записывал бы адреса и ФИО со страницы.
2. Скопируйте номер счётчика и впишите его в `app.js`: `const METRIKA_ID = '12345678';`. Пусто — метрика не подключается.
3. В счётчике «Цели» → «JavaScript-событие» добавьте нужные идентификаторы:

| Цель | Когда срабатывает |
|---|---|
| `file_loaded` | файл загружен (параметры: `ext`, `tasks`, `columnsFound`) |
| `file_error` | файл не прочитался |
| `mapping_manual` | колонки выбраны вручную |
| `km_manual` / `km_reset` | км введены вручную / очищены |
| `row_move` / `row_delete` | задание передвинуто / удалено |
| `km_recalc` | нажато «Пересчитать км» |
| `download` | скачан отчёт (параметры: `days`, `tasks`) |
| `download_blocked` | скачать не дали: не заполнены база или стоимость |
| `settings_open` | открыты настройки |
| `support_copy` | скопирован номер карты |

В Метрику уходят только эти события и числа — без адресов, ФИО и содержимого файла.

## Запуск

Откройте `index.html` через любой статический сервер, например `python3 -m http.server`, или включите GitHub Pages (Settings → Pages → Deploy from branch).

## Свой сервер (Linux, рядом с CRM «Лаборатория 3Д»)

Сайт статический, отдельного процесса у него нет. Его раздаёт тот же **Caddy**, что и CRM: скрипт кладёт файл `/etc/caddy/lab3d.d/marshrutnik.caddy`, а Caddy сам получает HTTPS-сертификат. Основной `Caddyfile` (его пишет `lab3d config`) не меняется — он уже подключает все файлы из `lab3d.d`.

Сначала должна быть установлена CRM (`deploy/linux/install.sh` в её репозитории).

1. **DNS.** У регистратора записи `A @` и `A www` для `маршрутник.рф` — внешний IP сервера (тот же, что у домена CRM). Если сервер тот же, что был на Windows, и IP не менялся — ничего менять не нужно.
2. **Скачать сайт на сервер** — в `/opt`, а не в домашнюю папку: Caddy работает от пользователя `caddy` и в закрытую домашнюю папку не заглянет.
   ```
   sudo git clone -b claude/vigilant-hopper-4qqja3 https://github.com/fantome6463/mlautosite.git /opt/marshrutnik
   ```
3. **Подключить:**
   ```
   sudo /opt/marshrutnik/deploy/linux/marshrutnik connect
   ```
   Это же ставит команду `marshrutnik`. Если включён `ufw`, порт просмотра по IP открывается сам; если сервер за роутером — пробросьте на нём порты 80, 443 и 8088.

Сразу после подключения сайт открывается **по IP**: `http://<IP сервера>:8088`, по домену — как только DNS укажет на сервер.

Дальше:

| Команда | Что делает |
|---|---|
| `marshrutnik` | статус: отвечает ли сайт, подключён ли к Caddy, куда указывает DNS, есть ли обновления |
| `sudo marshrutnik update` | обновить сайт из GitHub (перезапускать ничего не нужно) |
| `sudo marshrutnik connect` | переподключить (например, когда появилась запись `www`) |
| `sudo marshrutnik disconnect` | отключить сайт |
| `sudo marshrutnik domain <домен>` | сменить домен |
| `sudo marshrutnik port <N>` | порт просмотра по IP (`0` — выключить) |

Переезд с Windows: на старом сервере ничего переносить не нужно — данных у сайта нет. Достаточно шагов 2–3 на новом.

## Свой сервер (Windows, рядом с CRM «Лаборатория 3Д»)

Сайт статический, отдельного процесса у него нет. Его раздаёт тот же **Caddy**, что и CRM (New_Lab_3D): программа кладёт файл `marshrutnik.caddy` в `New_Lab_3D\deploy\sites.d\`, а Caddy сам получает HTTPS-сертификат. Основной конфиг CRM не меняется.

Домен — **маршрутник.рф** (в DNS и сертификатах: `xn--80aqgfgraqi2c.xn--p1ai`).

1. **DNS.** У регистратора добавьте записи `A @` и `A www` с IP сервера — тем же, что у домена CRM.
2. **Скачать сайт на сервер** (рядом с папкой CRM):
   ```
   git clone -b claude/vigilant-hopper-4qqja3 https://github.com/fantome6463/mlautosite.git
   ```
3. **Запустить `marshrutnik.bat`.** При первом запуске соберётся `Marshrutnik.exe` и откроется окно. Нажмите **«Подключить сайт»**.

Сразу после подключения сайт открывается **по IP**: `http://<IP сервера>:8088` (порт программа сама открывает в брандмауэре; если сервер за роутером — пробросьте этот порт на роутере). По домену он заработает, как только в DNS появятся записи.

В окне видно, работает ли сайт, подключён ли он к Caddy, куда указывает домен и есть ли обновления. Кнопки: *Подключить сайт*, *Обновить сайт* (скачивает новую версию из GitHub — перезапускать ничего не нужно), *Открыть сайт*; в меню «...» — *Указать папку CRM*, *Отключить сайт*. Закрытие окна на работу сайта не влияет.

То же из консоли: `marshrutnik.bat status | connect | update | disconnect`, `marshrutnik.bat crm D:\New_Lab_3D`.
